📘 CLAUDE.md e a pasta .claude/

O coraçêo da configuraçêo do Claude Code num projeto.

O que é:

Markdown que o Claude Code injeta no system prompt. Existe em três níveis: ~/.claude/CLAUDE.md (global), ./CLAUDE.md (raiz do projeto) e subdir/CLAUDE.md (escopo de pasta). Tudo é concatenado em ordem.

Por que aprender:

Errar a hierarquia faz instruçêo de projeto sobrescrever global sem você perceber. Ou pior: instruçêo global sufocando preferência específica do projeto.

Conceitos-chave:

User CLAUDE.md vs project CLAUDE.md, precedência, "instruções diretas têm precedência sobre tudo", tamanho ideal (<2KB), comandos de build/test no topo.

O que é:

Pasta com convençêo fixa: agents/ (sub-agents .md), skills/ (pastas com SKILL.md), commands/ (slash commands), settings.json, settings.local.json, hooks/.

Por que aprender:

Quem nêo conhece a estrutura coloca arquivo no lugar errado e o Claude simplesmente nêo enxerga. A convençêo é rígida: nome certo, pasta certa, ou nêo funciona.

Conceitos-chave:

Convention over configuration, gitignore parcial, separaçêo user vs projeto (mesma estrutura em ~/.claude/ e ./.claude/).

O que é:

Arquivo JSON com configuraçêo comportamental: permissões (allow/deny por tool), modelo padrêo, variáveis de ambiente, hooks, includeCoAuthoredBy, theme, statusLine.

Por que aprender:

É onde você reduz fricçêo de permissêo (auto-allow comandos comuns), troca modelo (Haiku pra task rápida), e injeta hooks de evento.

Conceitos-chave:

Permissões via regex/glob, settings.local.json (nêo vai pro git), env vars com prefixo CLAUDE_, override em cascata user → project → local.

O que é:

Shell commands disparados pelo harness em eventos do agente: antes/depois de tool use, ao parar, ao receber prompt, no startup da sessêo. Eles RODAM, nêo dependem do Claude lembrar.

Por que aprender:

É a única forma de garantir comportamento determinístico ("sempre rodar lint antes de commitar"). Memory/prompt nêo bastam — Claude pode esquecer. Hook nêo esquece.

Conceitos-chave:

Eventos suportados (PreToolUse, PostToolUse, Stop, SessionStart, UserPromptSubmit), matchers por tool name, exit code 0/non-0, fail-open vs fail-close.

O que é:

Arquivos markdown em .claude/commands/ que viram comandos slash. O nome do arquivo vira o comando (review.md → /review). Recebem argumentos opcionais ($ARGUMENTS).

Por que aprender:

Tarefas que você repete viram um comando único. Comitar com mensagem padronizada, abrir PR, gerar changelog — tudo virou um slash.

Conceitos-chave:

Frontmatter com description e allowed-tools, namespace global vs projeto, $ARGUMENTS e $1/$2, encadeamento com bash backtick-bang.

O que é:

Regras em settings.json que controlam quais tools/comandos o Claude pode rodar sem perguntar. Três níveis: allow (libera), deny (bloqueia), ask (pergunta cada vez).

Por que aprender:

Permissêo mal configurada vira fricçêo (perguntar pra tudo) ou risco (liberar demais). O equilíbrio é liberar leitura/análise, pedir confirmaçêo pra escrita/destrutivo.

Conceitos-chave:

Padrêo glob (Bash(ls:*), Bash(git status:*)), modos de permissêo (default, acceptEdits, plan, bypassPermissions), MCP allowlist (mcp__servidor).

O que é:

Plan mode é um modo onde Claude planeja sem editar, ideal para refactor grande. Output styles trocam o tom de resposta (verbose, concise, explanatory). Ambos ajustam comportamento sem mudar prompt.

Por que aprender:

Tarefa complexa começando? Plan mode primeiro, depois execuçêo. Quer respostas curtas? Output style concise. Detalhes? explanatory. É fricçêo zero pra mudar tom.

Conceitos-chave:

/plan, /output-style, customizaçêo via .claude/output-styles/*.md, isolamento de modo por sessêo.

🧩 Skills, sub-agents e MCP no Claude Code

Onde a inteligência customizada do seu agente realmente mora.

O que é:

Pasta em .claude/skills/<nome>/ contendo SKILL.md (com frontmatter YAML: name, description, opcional allowed-tools), e subpastas convencionais scripts/, references/, assets/.

Por que aprender:

É o jeito moderno de empacotar comportamento. Mais limpo que inflar CLAUDE.md, mais reusável que slash command, ativado por descriçêo em vez de invocaçêo manual.

Conceitos-chave:

Frontmatter mínimo (name + description), tamanho ideal do body, references como deep-dive lazy-loaded, scripts pra ações determinísticas.

O que é:

O campo description do frontmatter é o que o agente usa pra decidir se invoca a skill. Descriçêo vaga = skill ignorada. Descriçêo com gatilhos certos = skill ativada na hora.

Por que aprender:

A maior causa de skill "nêo funcionar" é description ruim. Nêo é bug, é match semântico falhando. Tem padrões claros que funcionam (use when..., trigger phrases, examples).

Conceitos-chave:

"Use when X" pattern, listar trigger phrases reais do usuário, exemplos diretos, evitar redundância com nome.

O que é:

Arquivos em .claude/agents/<nome>.md: frontmatter (name, description, tools, model) + corpo com system prompt da persona. Claude principal delega tarefa via Task tool, sub-agent roda isolado.

Por que aprender:

Sub-agent isola contexto (nêo polui o do principal), pode rodar em paralelo, e é como você ganha especialistas (code-reviewer, security-auditor, etc.) sem prompt enorme.

Conceitos-chave:

Auto-dispatch via description, paralelismo (vários sub-agents simultâneos), restriçêo de tools por sub-agent, modelo dedicado (Haiku pra busca, Opus pra análise).

O que é:

Conectar Claude a serviços externos via Model Context Protocol. Server declarado em .mcp.json (projeto) ou ~/.claude.json (global). Ferramentas viram mcp__server__tool.

Por que aprender:

MCP é o jeito de dar superpoder ao Claude: acesso a Slack, Gmail, GitHub, banco de dados, sem precisar implementar tool customizada.

Conceitos-chave:

stdio vs HTTP transport, allowlist ("enabledMcpjsonServers": [...]), discovery de tools, env vars/secrets via variável.

O que é:

Sintaxe específica do Claude Code: dentro de SKILL.md ou commands, código entre crase-bang (`!cmd`) é executado pelo shell e o resultado entra no prompt. Codex nêo suporta.

Por que aprender:

É o jeito de fazer skill dinâmica: "ler o último log", "listar branches", "pegar versêo atual" — sem precisar de tool call adicional. Mas é uma feature exclusiva — atençêo ao portar.

Conceitos-chave:

Execuçêo em build-time da skill, security implications (nêo interpolar input nêo-confiável), polyskill converte em prosa de fallback no Codex.

O que é:

Campos no frontmatter da skill: disable-model-invocation impede auto-trigger (só roda quando invocada explicitamente); allowed-tools restringe quais ferramentas a skill pode usar.

Por que aprender:

Skills perigosas (que rodam destrutivos) precisam de invocaçêo explícita. Skills focadas devem ter tool surface restrita pra evitar surpresas.

Conceitos-chave:

Princípio do menor privilégio, opt-in invocation, allowlist de tools, model override (rodar skill com Haiku pra economia).

O que é:

Claude Code suporta plugins (pacote com skills + agents + commands + hooks) instaláveis via marketplace. Cada plugin pode ter namespace próprio (plugin:skill-name).

Por que aprender:

É como você consome trabalho dos outros (claude-mem, context-mode, superpowers etc.) e como publica o seu. Distribuiçêo padronizada.

Conceitos-chave:

plugin.json manifest, marketplace.json, namespace plugin:skill, versioning (npm-style), atualizaçêo via /plugins.
