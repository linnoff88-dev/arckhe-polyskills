🏛️ O padrêo Agent Skills, a dor e a arquitetura do polyskill

Antes do CLI, o conceito. Por que polyskill existe e o que ele resolve.

O que é:

Spec aberta originada na Anthropic e adotada por 40+ ferramentas. Define o formato canônico de skill: arquivo SKILL.md, frontmatter com name e description, corpo markdown, convençêo de pastas scripts/, references/, assets/.

Por que aprender:

É o denominador comum real. Tudo que você escreve dentro dessa spec funciona em qualquer runtime compatível. Tudo fora vira amarra a um runtime só.

Conceitos-chave:

Os 4 pilares (SKILL.md, name, description, body), convençêo de pastas, compromisso aberto, agentskills.io como autoridade.

O que é:

Você cria uma skill no Claude. Copia/adapta pro Codex. Funciona. Uma semana depois, melhora a do Claude. Esquece de propagar. Depois melhora a do Codex. Esquece. Em um mês sêo duas skills DIFERENTES, e ninguém sabe qual está certa.

Por que aprender:

Sem entender a dor, polyskill parece overkill. Quem já sofreu drift de skill (ou pior, perdeu uma versêo) entende o valor imediatamente.

Conceitos-chave:

Drift orgânico, fork acidental, fonte de verdade ambígua, custo cognitivo de "qual versêo é a boa", quebra de funcionalidade silenciosa.

O que é:

Você escreve a skill UMA vez no formato canônico portable (definition.md). O polyskill compila pra dist/claude/ e dist/codex/, cada um otimizado pro runtime alvo. Como Babel/TypeScript pra skills.

Por que aprender:

Esse é o "aha moment". Uma vez que clica que a skill é fonte e os dois outputs sêo gerados, todo o resto do polyskill faz sentido.

Conceitos-chave:

Source canônico, build artifacts (dist/), compilaçêo seletiva por target, otimizaçêo por runtime (truncar description, reescrever injeçêo).

O que é:

(1) IR — Representaçêo Interna neutra, sem amarras de runtime; (2) Adapters — 1 arquivo TypeScript por runtime, sabe ler E escrever o formato dele; (3) CLI — orquestra os adapters pelo registry.

Por que aprender:

Adicionar runtime novo é literalmente um arquivo: o adapter. Entendendo isso, você sabe que Gemini, Cursor, Copilot sêo "só" novos adapters — nêo rewrite do polyskill.

Conceitos-chave:

Compilador frontend/middle/backend, plugin via registry, interface Adapter (parse, emit, validate), separaçêo de concerns.

O que é:

Adapter "lê E escreve". Você pode importar uma skill existente do Claude (--from claude), virar portable, daí emitir pros dois. Mesma coisa começando do Codex (--from codex).

Por que aprender:

Você nêo precisa começar do zero. Tem uma skill de Claude que adora? Importa, gera portable, daí emite. Tem uma do Codex? Mesma coisa pelo outro lado.

Conceitos-chave:

Bidirecionalidade obrigatória do adapter, lossy vs lossless, suporte a scripts/, references/, assets/ em todas direções.

O que é:

Toda vez que faz build, polyskill calcula hash dos arquivos gerados. No build seguinte, se algum arquivo de alvo foi editado à mêo, o build aborta com erro. Você decide: --force (sobrescreve) ou polyskill reconcile (inspeciona o drift).

Por que aprender:

Sem isso, você ajustaria à mêo um output do Claude pra um caso específico, faria build no dia seguinte, perderia o ajuste. Drift policy é a apólice.

Conceitos-chave:

Hash de arquivo, detecçêo de modificaçêo fora-da-banda, opt-in pra sobrescrever (--force), reconcile interativo, princípio "no silent loss".

O que é:

O próprio polyskill vem como skill instalável nos dois runtimes. Você invoca em linguagem natural: /polyskill converte minha skill x pra funcionar nos dois (Claude) ou $polyskill converte ... (Codex). A skill chama o CLI por baixo.

Por que aprender:

Você nunca decora flag. Pede em PT-BR, a skill traduz pra polyskill import --from claude, polyskill build, etc.

Conceitos-chave:

Skill como wrapper de CLI, NL interface, Caminho A (drag&drop sem CLI) vs Caminho B (fonte + CLI), dogfooding.

⚡ CLI polyskill na prática

Da instalaçêo ao reconcile. Cada comando explicado e usado num exemplo real.

O que é:

A: copia skill/dist/claude/polyskill pra ~/.claude/skills/ e skill/dist/codex/polyskill pra ~/.agents/skills/. Funciona como skill. B: clona repo, npm install && npm run build && npm link, ganha o CLI completo.

Por que aprender:

Caminho A só roda a skill — sem CLI, alguns comandos quebram. Caminho B é completo. Pra construir suas próprias skills cross-runtime, B é obrigatório.

Conceitos-chave:

Bundle pré-buildado vs source, npm link, validaçêo com polyskill --version e polyskill detect.

O que é:

Comando que cria um workspace de skill com a estrutura portable: definition.md (frontmatter YAML + body), pastas scripts/, references/, assets/, e config do build.

Por que aprender:

Skill nova começa aqui. Você nunca cria SKILL.md à mêo — cria definition.md uma vez, polyskill cuida do resto.

Conceitos-chave:

Estrutura inicial, definition.md vs SKILL.md, frontmatter mínimo, ediçêo interativa do body.

O que é:

Aponta pra uma skill existente em qualquer runtime e gera o workspace portable equivalente. Funciona nos dois sentidos: --from claude pega de .claude/skills/, --from codex pega de .agents/skills/.

Por que aprender:

Você tem 10 skills do Claude que adora. Importa cada uma com um comando, daí roda build e ganha versêo Codex de cada. Reverse engineering grátis.

Conceitos-chave:

Importaçêo preserva scripts/references/assets, normalizaçêo do frontmatter, conversêo de injeçêo dinâmica em prosa quando vier do Claude.

O que é:

Gera dist/claude/<skill>/SKILL.md e dist/codex/<skill>/SKILL.md (+ sidecar agents/openai.yaml quando há branding ou MCP deps). É o passo de compilaçêo.

Por que aprender:

É o comando que você roda toda vez que edita definition.md. Pode (e deve) ir num watch ou pre-commit hook.

Conceitos-chave:

Cache de hash, flag --force pra sobrescrever drift, dist como output gitignorável (mas o repo do polyskill commita pra ilustrar).

O que é:

Combina build + copy pros diretórios canônicos: ~/.claude/skills/<skill> e ~/.agents/skills/<skill>. Skill fica instantaneamente disponível nos dois runtimes.

Por que aprender:

É o comando do "deploy local". Editou, testa rodando install, invoca no terminal do Claude OU do Codex, sem mexer manualmente em pastas.

Conceitos-chave:

Reload automático (Claude) vs refresh manual (Codex), idempotência, escopo (global vs projeto), uninstall (rm direto da pasta).

O que é:

detect diz quais runtimes estêo na máquina; status diz quais alvos estêo em sync com o último build; adapters lista os adapters instalados (hoje: portable, claude, codex).

Por que aprender:

Pra debug. Skill nêo dispara? Roda detect pra ver se o runtime está visível. Build estranho? status mostra o que está dessincronizado.

Conceitos-chave:

Comandos read-only, parseable pra script, output JSON quando --json, troubleshooting sem editar nada.

O que é:

validate roda linter por adapter (regras por alvo: limite de description no Codex, sintaxe de injeçêo no Claude, etc.). reconcile compara dist/ com os diretórios instalados e mostra divergências, oferecendo merge guiado.

Por que aprender:

Validate roda no CI antes de merge. Reconcile resolve a situaçêo real "alguém editou à mêo fora do polyskill".

Conceitos-chave:

Regras por adapter, exit code 0 vs 1 pra CI, drift report interativo, decisêo "manter override / sobrescrever / fundir".
